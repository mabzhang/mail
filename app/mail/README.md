# Mail

Mail 1.0.1 是 Hana 的邮件工作台，支持多邮箱只读阅读、邮件总结、区间回顾、草稿、AI 润色与回复、本地联系人、附件和工作日历。发送前必须由你查看预览并确认。

## 安装

需要 Hana 1.5.48-beta 或更新版本。在 Hana 扩展市场的「已安装」页面选择从 ZIP 安装，导入 app-mail-1.0.1.zip，查看并批准所需权限，然后从应用入口打开 Mail。安装包已包含 JavaScript 运行依赖，无需另装 npm 包。此包不会自动安装到你的环境，也不会自动发布到市场。

首次打开时，邮箱、模型、签名、企业域名和快捷短语均为空。进入设置填写自己的邮箱地址、IMAP / SMTP 主机和端口、第三方客户端授权码；服务地址请向邮箱服务商获取。应用不会替你选择公司或邮箱服务商。

## 授权码与本地数据

邮箱授权码只保存在本次 App 后台运行的内存中，不写入账户文件。App 后台重新加载、关闭或宿主退出后，需要在设置中编辑原账号并重新填写授权码；仅切换页面不一定重启后台。历史邮件缓存、草稿、发送记录、联系人、日历与总结保存在应用自己的数据目录中。它们包含你的邮件资料，请按个人数据管理。发送前临时大内容使用本地密钥加密；这不等同于整个数据目录加密。

Mail 使用独立 id `mail`，与旧邮件助手的数据目录分开。不会自动读取或搬移旧应用的账号、授权码、签名、公司通讯录或邮件资料。旧应用与数据可保留。

## 模型与网络

模型目录与推理统一使用 Hana 公共 SDK，不读取、保存或直连供应商 API 密钥。手动生成总结、润色、回复和风格学习会把所选邮件文字交给你在 Hana 配置的模型，费用由该模型配置决定。自动总结默认关闭，开启后按更新间隔处理；本次运行中发生失败后暂停该日自动重试，需点击手动更新。应用重启后会按照已保存的开关重新开始扫描。

外部天气默认关闭；开启后才访问天气服务。按 IP 选择城市会访问 IP 服务，可改用手动选城市；不读取设备定位，不保存公网 IP。天气与邮箱功能相互独立。

后台通过 Hana 受管 native Node 运行时连接你填写的 IMAP / SMTP 服务器，因此申请执行、native 与外部联网权限。这种运行方式的系统权限由宿主管理；天气 HTTP 白名单不限制 native 邮箱连接。Windows 可能需要宿主先完成原生运行身份准备；失败时可在设置查看诊断，不自动降级为更宽的运行权限。

可供宿主 Agent 使用的三个工具均为只读：公开账号、读邮件、读已生成总结。工具不会发信、删除邮件或触发总结生成。邮件正文被视为不可信数据。

## 发送与恢复

发送流程是保存草稿 → 预览 → 核对提醒 → 人工确认。更改内容需要重新预览。确认票据有时效并绑定内容，重复确认不会重复投递。SMTP 中断或后台退出导致结果不确定时不会自动重发，请先查看邮箱服务商的已发送记录。

邮件阅读不改已读标记；脚本、表单与危险样式被清理，外部图片默认阻止。只有你明确选择加载时才允许图片网络请求。签名由你填写或主动提取，不预填署名。
