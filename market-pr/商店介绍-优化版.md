# Mail — 把邮箱变成工作台

**Mail 是 Hana 里的原生多邮箱工作台**：不只是一个收件箱，而是把「读信、回顾、起草、AI 润色、联系人、日历、发送确认」放在同一张桌子上。所有账号、主机和模型都由你配置，新装即白纸，没有预置品牌、预填账号或隐藏的第三方服务。

需要 Hana 1.5.48-beta 或更新版本。App ID：`mail`。

## 为什么你需要它

- **多账号，一次看完**：连接多个 IMAP 邮箱，统一阅读、搜索与筛选；**只读操作绝不改变邮件已读状态**，查看过什么只有你知道。
- **回顾比翻找更快**：手动生成当日总结，或对任意时间段生成区间回顾，把几十封邮件压缩成一段有结构的中文摘要；总结可以重复读，不会反复花模型费用。
- **AI 替你写，也学你写**：用你在 Hana 中选定的模型润色邮件、起草回复，甚至学习你个人的写作风格；选定邮件文字才会发给模型，费用取决于你的模型配置。
- **发送前永远先确认**：写好的邮件先落草稿，看预览、核对收件人、附件与提醒，再由你人工点确认才发出。发送状态不确定时**不会自动重发**，宁可停手，不冒进。
- **邮件里挖出待办和会议**：从邮件整理会议与跟进事项，配套本地工作日历，支持 ICS 导入导出，邮箱与日程在同一条流水线上。
- **本地联系人管理**：联系人、CSV 导入、分组、签名、附件与草稿全部落在你的 App 私有数据目录。

## 安全与隐私设计

- **授权码不落盘**：IMAP/SMTP 授权码只保存在 App 后台本次运行的内存里，后台重新载入或退出后即失效，需要重新填写。
- **模型密钥不过手**：Mail 不保存、不直连任何模型供应商的 API 密钥，推理全部走 Hana 的宿主模型通道。
- **Agent 工具只读**：暴露给宿主的三个工具只读公开账号信息、邮件与已生成总结，**不能发信，也不能触发总结生成**。
- **外部连接可预期**：邮箱连接只访问你填写的 IMAP/SMTP 服务器；天气默认关闭，启用后使用中国气象中心或 MET Norway；按 IP 选城市只在主动操作时访问 IP 服务，不读取设备定位、不保存公网 IP；邮件外部图片默认阻止，只有你主动加载才请求对应网站。
- **数据边界说清楚**：缓存、草稿、联系人、总结与日历保存在 App 私有数据目录，**整个目录未加密**，请按本地磁盘的安全等级看待它们。

## 权限清单（安装时逐项可见）

| 声明能力 | 用途 |
| --- | --- |
| `app/tools.expose-to-model` | 向宿主 Agent 暴露三个只读工具（公开账号信息、读邮件、读已生成总结） |
| `app/runtime.execute` | 由 Hana 启动受管邮箱后台 |
| `app/runtime.native` | 受管 native Node 后台访问邮箱协议与本地数据，不升级为 local-machine |
| `app/runtime.network` | native IMAP/SMTP 外联，及用户启用后的天气等外部连接 |
| `app/models.infer` | 总结、润色、回复与风格学习调用你选定的模型，可能产生费用 |

## 快速上手

1. 在 Hana 扩展市场的「已安装」页导入官方 ZIP，核对并批准权限。
2. 打开 Mail，填写自己的邮箱地址、IMAP/SMTP 主机与端口、客户端授权码。
3. 在 Hana 模型目录选定一个模型（总结、润色、回复用）。
4. 自动总结与天气默认关闭，按需开启。
